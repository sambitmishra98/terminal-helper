# Audit — July 2026

Phase 1 deliverable of the terminal-helper revamp. Every finding below was
verified by reading the code, running `bash -n` and `shellcheck` (v0.8.0) on
all 49 tracked `*.sh` files, and checking CI history. Nothing here has been
changed yet; fixes land in Phase 2+ after approval.

Classifications: **BUG** (malfunctions when run), **INC** (inconsistency),
**DW** (dead weight), **DW-LLM** (dead weight because an LLM can regenerate it
on demand — see §6), **POL** (policy violation), **DQ** (design question).

Baseline: `main` at `c93ad53c`, remote reconciled (Phase 0, 2026-07-07).

## 1. Bugs

| ID | Location | Finding |
|----|----------|---------|
| B1 | `bin/set-paths` | Trailing-slash exports plus mixed concatenation produce double slashes: `MESHES=$SUPPLEMENTARY/gmsh-files/` where `SUPPLEMENTARY` already ends in `/` → `/scratch/supplementary//gmsh-files/`. Same for `PARTITIONS`, `DOWNLOADS`, `EXTRACTS`, `INSTALLS`, and the `source "$SAMBITMISHRA98/terminal-helper/..."` line. |
| B2 | `lib/installers/installations/base.sh` | Not a script: a pasted LLM transcript. If executed it `cd`s to a personal path, **rewrites itself** via heredoc, runs network self-tests, then `git add / commit / push`. |
| B3 | `gcc.sh`, `opencl.sh`, `openmpi.sh`, `pyfr.sh` (installers) | Call `setup_base` and `export_all_versions`, which are **defined nowhere in the repo**; rely on `PKG_DOWNLOAD` / `PKG_LOCAL` / `VENV_LOCAL` / `GIT_LOCAL`, which `set-paths` never exports. Guaranteed failure on any machine. |
| B4 | `lib/clusters/print-env-info.sh:6` | Sources `$(dirname …)/../colors.sh` → resolves to `lib/colors.sh`, which does not exist (`colors.sh` lives in `lib/common/`). Fails on every source. |
| B5 | `lib/projects/pyfr/setup-worktree.sh:56,136` | Checks/activates venv at `${VENVS}/${base_branch}`, but venvs are created at `${SAMBITMISHRA98_PYFR_VENVS}${name}` (= `.venvs/sambitmishra98/PyFR/<name>`). The guard can never pass against a venv made by `setup-venv.sh`. |
| B6 | `lib/projects/pyfr/setup-worktree.sh:117-125` | Merge-conflict abort is commented out: a conflicted `git merge` is ignored and the function continues to build a half-merged tree. |
| B7 | `lib/projects/pyfr/setup-worktree.sh:156-172` | `setup_worktree_testbed` error checks (wrong directory, empty casename, no features) print an error **but do not `return`** — execution continues regardless. |
| B8 | `lib/clusters/sync.sh:17,23`; `lib/projects/pyfr/cube-mesh-linker.sh:17,22`; `profession/pyfrs_extract.sh` (`check_dependencies`) | `exit 1` inside functions that are meant to be sourced — kills the login shell (or SLURM job step) instead of returning. |
| B9 | `lib/common/add_installation.sh:59` | `remove_all_installation_paths` resets `PATH` to a hardcoded `/home/sambit/.local/bin:...` desktop PATH. On a cluster this destroys the session (no module paths, no scheduler tools). |
| B10 | `lib/projects/pyfr/setup-venv.sh:18` | Uses `C_YELLOW`/`C_RESET` before they are declared at line 26 (deactivate branch prints escape-less text). Cosmetic. |
| B11 | `lib/installers/installations/libffi.sh:64` | SC2189: redirection placed before the pipe it should feed — the pipeline is broken as written. |
| B12 | `.github/workflows/shellcheck.yml` + CI history | ShellCheck CI has **failed on every push** (verified via `gh run list`; last 5 runs all red). Current tally: 14 errors, 42 warnings, 184 notes across 42 of 49 files. Also, the `'*.sh'` glob means the `.Spitfire`, `.LaunchMixed`, `.Launchcpu/gpu` job scripts are never checked. |
| B13 | `bin/terminal-env:11` | `return 1` at file top-level is valid only when sourced; direct execution triggers a bash error and continues. `REPO_ROOT=$1` unquoted. |

## 2. Inconsistencies

| ID | Location | Finding |
|----|----------|---------|
| I1 | `bin/set-paths` vs all consumers vs docs | No single path convention: exports carry trailing slashes, consumers sometimes add `/` and sometimes concatenate bare, docs write paths without trailing slashes. Root cause of B1. |
| I2 | `bin/set-paths` | Username baked into variable names (`SAMBITMISHRA98_PYFR*`), with redundant aliases: `PYFR_BRANCHES` ≡ `SAMBITMISHRA98_PYFR`, `PYFR_VENVS` ≡ `SAMBITMISHRA98_PYFR_VENVS`. `print_paths` renders the aliases as parent/child, which is false. |
| I3 | `docs/path-contract.md` | Documents 7 of the ~17 exported variables. Missing: `MESHES`, `PARTITIONS`, `DOWNLOADS`, `EXTRACTS`, `INSTALLS`, and the entire `SAMBITMISHRA98_*` family. |
| I4 | Headers | Stale filenames in usage headers: `bin/set-paths` says "source set-paths-dir.sh"; `bin/terminal-env` says "terminal_addon.sh"; `add_installation.sh` says "installations-linker.sh"; `etc/local-paths.sh` says "local-only-paths-template.sh". |
| I5 | `setup-worktree.sh:140` vs `setup-venv.sh:116` | Two install idioms for the same job: deprecated `python3 setup.py develop` vs `pip install -e .`. |
| I6 | `setup-venv.sh` | `setup_pyfr_venv <venv-type> <name>`: `<venv-type>` is captured and never used. `setup_pyfr_venv_with_deps` claims to "create / reuse" but `setup_pyfr_venv` hard-fails if the venv exists — reuse is impossible. |
| I7 | `lib/installers/installations/` | Two installer generations coexist: old (B3 family: undefined helpers, unquoted, `eval`) and new (`ucx.sh`, `mpich.sh`, `osu.sh`, `openssl.sh`, `python.sh`: `DOWNLOADS`/`EXTRACTS`/`INSTALLS`, quoted, logged). |
| I8 | `lib/common/colors.sh` | Exists but nothing uses it — every script redefines its own palette locally; the one script that tries to source it does so via a broken path (B4). |
| I9 | `README.md` | Root README is a **symlink** to `docs/README.md`. Works on GitHub's web UI today, but breaks in tarball exports, Windows checkouts, and any tool that doesn't follow symlinks; the "entry point" also then claims docs-relative links that are wrong from the root. |
| I10 | `lib/clusters/sync.sh:11` | Machine identity hardcoded as a default (`RSYNC_HOST:=sambit@spitfire.engr.tamu.edu`) rather than coming from a machine profile. |
| I11 | Repo hygiene | `quick-git-commands/` is an empty on-disk directory (untracked); `.containers/` is documented as reserved in three places but has never existed. |

## 6. LLM-commodity triage of automation scripts

Per the owner's directive (2026-07-07): scripts whose content is common
knowledge to an LLM (Claude/Codex can regenerate them from the internet on
demand) should be scratched. Scripts encoding personal/site/research knowledge
stay. The durable asset is the **convention** (where things download, extract,
install; how paths get onto `PATH`), not the recipes.

## 7. Design questions

**DQ1 — Path convention.** Options: (a) no trailing slashes anywhere, joins
are explicit `${A}/${B}`; (b) keep trailing slashes, forbid `/` at joins.
**Recommendation: (a)** — matches docs, matches every other Unix convention,
makes `doctor` checks trivial (`[[ $p != */ && $p != *//* ]]`).

**DQ2 — Variable naming.** Options: (a) generic names only (`PYFR_BRANCHES`,
`PYFR_VENVS`, with `GITHUB_USER` as a variable used in *values*, never in
*names*); (b) keep `SAMBITMISHRA98_*` as silent compatibility shims for one
transition period; (c) keep both families forever.
**Recommendation: (a) + (b)** — generic canonical names in Phase 3; shims
exported quietly, listed in one place, removed when muscle memory adapts.

**DQ3 — Installer replacement.** Options: (a) delete all commodity recipes,
keep `add_installation_to_path` + `docs/installing.md` contract; (b) keep the
new-generation scripts (`ucx.sh` etc.) as exemplars; (c) rewrite everything on
a unified framework. **Recommendation: (a)** per §6 — (c) is exactly the kind
of automation the owner has declared obsolete.

**DQ4 — Reference data (P4).** Options: (a) move to
`/scratch/supplementary/references/` and gitignore, with a pointer doc;
(b) separate `research-references` git repo (survives machine loss, versioned);
(c) leave in place. **Recommendation: (b)** — this is irreplaceable digitized
literature data; it deserves its own backed-up repo, and terminal-helper stops
carrying 8.5 MB of CFD curves. (a) is acceptable if a second repo feels heavy,
but supplementary is explicitly "not synced by default", i.e. one disk failure
from loss.
**Decision (owner, 2026-07-07): (c) — leave in repo for now; revisit with the
profession/ relocation question in Phase 5.**

**DQ5 — README.** Options: (a) real root `README.md` (entry point) and demote
`docs/README.md` to a docs index; (b) keep symlink. **Recommendation: (a)**.

**DQ6 — Committed IP/hostname in history (P1).** Sanitizing the file fixes the
tip; `10.125.213.39` and hostnames remain in git history. Options: (a) sanitize
tip only, accept history (IP is TAMU-internal, repo already public);
(b) history rewrite + force-push (destructive; needs explicit approval).
**Recommendation: (a)** — the information is low-sensitivity (internal RFC-1918
IP, hostname already public via DNS); a rewrite invalidates every clone for
marginal gain. Owner's call.
**Decision (owner, 2026-07-07): (a) — sanitize the tip only; no history
rewrite.**

**DQ7 — `update_feature_branch` (setup-venv.sh).** It force-pushes (with
lease) and rewrites `git config` in PyFR clones — repos this project has
declared off-limits to automation. Options: (a) move to PyFR-side tooling /
profession; (b) keep but gate behind confirmation; (c) drop.
**Recommendation: (a)** — it is PyFR workflow, not terminal setup.

**DQ8 — Machine profiles (Phase 3 preview).** Options: (a) tracked templates
`etc/machines/<name>.sh.example` + gitignored real `etc/machines/<name>.sh`,
selected by hostname; (b) single gitignored `~/.terminal-helper.conf`.
Decision deferred to the Phase 3 proposal; both keep real values out of git.
